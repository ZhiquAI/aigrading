## 2. AI 调用层对比

### 2.1 架构差异

**grading-platform-v2:**
- 使用独立的 `ai-gateway` 包统一管理 AI 调用
- 支持多提供商自动切换（failover机制）
- 后端统一处理 API 限流、重试、错误恢复
- 调用链路: 前端 → API Server → ai-gateway → 多提供商

**ai-智能批改助手_副本:**
- 前端直连 AI 服务（Google Gemini / OpenAI兼容 / 智谱GLM）
- 自研 `rate-limiter` 模块处理限流
- `callOpenAICompatible` 函数支持多后端
- 调用链路: 扩展 → AI Provider（直连）

### 2.2 核心代码位置

| 功能 | grading-platform-v2 | ai-智能批改助手_副本 |
|------|---------------------|---------------------|
| AI 网关 | `packages/ai-gateway/src/index.ts` | - |
| AI 服务 | - | `services/ai-service.ts` |
| 限流器 | 后端统一处理 | `services/rate-limiter.ts` |

## 8. 总结与建议

### 8.1 架构选择建议

| 场景 | 推荐方案 | 原因 |
|------|----------|------|
| **商业化/企业版** | grading-platform-v2 | 配额、激活码、云端存储 |
| **快速原型/个人工具** | ai-智能批改助手_副本 | 功能完整、易于调试 |
| **长期维护** | grading-platform-v2 | 架构清晰、模块化好 |

### 8.2 功能迁移建议

若要将 ai-智能批改助手_副本 的功能迁移到 grading-platform-v2：

1. **学科专项规则** → 提取到 `domain-core` 或配置中心
2. **整数分值校验** → 在 `grading-service` 中增强
3. **评语去重** → 作为后端处理或前端展示优化
4. **自动阅卷** → 扩展前端状态机
5. **桌面通知** → 使用 Service Worker

### 8.3 核心差异总结

- **grading-platform-v2**: 企业级架构，注重扩展性、配额管理、云端同步
- **ai-智能批改助手_副本**: 功能和体验优先，注重批改精度、学科适配、用户体验

两个项目代表了不同的设计理念：v2 是「平台化思维」，副本是「产品化思维」。
